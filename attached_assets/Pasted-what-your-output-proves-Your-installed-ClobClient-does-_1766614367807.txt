what your output proves

Your installed ClobClient does not have set_wallet_address (and no wallet/funder setter methods at all).
Only get_address() exists. So any code that tries to call set_wallet_address() will crash (as you saw).

The client supports funder= in the constructor, which is the correct way to do proxy/funder trading in your version:

ClobClient(host, chain_id, key, creds, signature_type, funder, builder_config)


So: stop trying to “set wallet address” after creation. You can’t in this version.

why you still get invalid signature

With Polymarket CLOB, invalid signature almost always means:

you’re signing orders with an EOA key that doesn’t match what the server expects for that request, OR

your orders are being signed with the wrong “mode” (signature_type) / wrong proxy (“funder”) combination, OR

your API creds were derived under a different config than you’re using to trade (most common in your situation).

Given your setup (EOA signer + proxy funder), the most likely issue is:

✅ you generated/loaded API creds that don’t correspond to the exact trading identity/config you’re using now

If you generated POLYMARKET_API_KEY/SECRET/PASSPHRASE earlier using a client without signature_type=1 and/or without funder=..., then later you try to trade with a new client with funder/proxy mode, the server can reject signatures because auth + signing context are inconsistent.

2) regenerate API creds using the same constructor config you will trade with

This is the big one.

Run this once on the VPS (and then put the printed values into .env):

import os
from dotenv import load_dotenv
from py_clob_client.client import ClobClient

# use the same key normalization you confirmed in step 1
pk_norm = pk.replace("0x","").strip()

client = ClobClient(
    "https://clob.polymarket.com",
    key=pk_norm,
    chain_id=137,
    signature_type=1,
    funder=proxy,
)

print("EOA signer:", client.get_address())
print("Proxy funder:", proxy)

creds = client.create_or_derive_api_creds()
print("\nSET THESE IN .env:\n")
print(f"POLYMARKET_API_KEY={creds.api_key}")
print(f"POLYMARKET_API_SECRET={creds.api_secret}")
print(f"POLYMARKET_API_PASSPHRASE={creds.api_passphrase}")
PY

about “builder keys”

You’re right: you generally should not be using builder keys for trading orders here.
Builder keys are commonly for builder endpoints / infra access, not for executing trades on behalf of a wallet. Your logs already showed:
Unauthorized/Invalid api key when using builder fallback.

So: remove builder fallback and rely only on derived API creds from your EOA/proxy config.
