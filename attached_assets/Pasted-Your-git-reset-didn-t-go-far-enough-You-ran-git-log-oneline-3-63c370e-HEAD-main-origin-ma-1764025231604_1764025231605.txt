2. The likely bug inside addReferralCode

Your helper (from grep):

function addReferralCode(url: string): string {
  const referralCode = "q2XDjZW";
  
  // Check if URL already has query parameters
  if (url.includes("?")) {
    return `${url}&via=${referralCode}`;
  }
  // (I assume you have a `return `${url}?via=${referralCode}`` here)
}
...
const referralUrl = addReferralCode(market.url);


Two big problems:

a) It assumes url is always a valid string

If any market has market.url undefined / null / empty:

addReferralCode(market.url);   // market.url === undefined
// -> url.includes("?")  → TypeError: Cannot read properties of undefined (reading 'includes')


That will blow up the workflow run and may stop the whole function before it reaches the Telegram call.

b) It can break HTML for Telegram

If you send:

const telegramMessage = `
<b>Market:</b> ${referralUrl}
`;


with parse_mode: "HTML":

When there’s already a ? in the URL, you now insert &via=....

A bare & in HTML must be escaped as &amp;.

Telegram is strict about entity parsing; a bad &something can cause “can’t parse entities” errors and the message fails.

So even if the workflow does run, the final step “send message to Telegram” might be failing every time.

3. How to fix addReferralCode properly

Replace your helper with this defensive version:

function addReferralCode(rawUrl: string | undefined | null): string {
  const referralCode = "q2XDjZW";

  // Guard against missing/invalid URLs
  if (!rawUrl || typeof rawUrl !== "string") {
    console.error("[referral] Missing or invalid URL, skipping:", rawUrl);
    return "";
  }

  const url = rawUrl.trim();
  if (!url) {
    console.error("[referral] Empty URL, skipping");
    return "";
  }

  // Optional: only touch Polymarket links
  if (!url.includes("polymarket.com")) {
    return url;
  }

  // Add query param safely
  const withParam = url.includes("?")
    ? `${url}&via=${referralCode}`
    : `${url}?via=${referralCode}`;

  return withParam;
}


And when building the message:

const referralUrl = addReferralCode(market.url);
const finalUrl = referralUrl || market.url || "";

// If you use HTML parse_mode, escape &
const safeUrl = finalUrl.replace(/&/g, "&amp;");

const telegramMessage = `🔮 <b>New Polymarket Market!</b>

<b>Question:</b> ${escapedQuestion}

<b>Market:</b> ${safeUrl}
`;


This way:

No more includes on undefined.

If anything about the URL is weird, you log and do not crash the workflow.

Telegram gets a safe URL string with &amp; so HTML parsing won’t fail.
