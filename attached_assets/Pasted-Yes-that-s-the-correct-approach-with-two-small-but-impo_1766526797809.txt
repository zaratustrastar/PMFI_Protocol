Yes — that’s the correct approach, with two small but important tweaks to make it robust:

Method name: in most py_clob_client versions the method is create_or_derive_api_key() (not create_or_derive_api_creds()), and it returns an object/dict you pass into set_api_creds().
Your stack trace shows you’re in py_clob_client/client.py and it’s failing at assert_level_2_auth(), which means set_api_creds() was never called — so adding that is exactly right.

Do it once, not in a tight loop: derive/set creds during client initialization (or cache them) rather than re-deriving every iteration.

Here’s the “safe” patch pattern right after client creation:

# after: client = ClobClient(...)

# Enable L2 auth (required for posting orders)
try:
    creds = client.create_or_derive_api_key()   # <- most common name
    client.set_api_creds(creds)
except Exception as e:
    logger.exception("Failed to init Polymarket L2 API creds; cannot post orders")
    raise


If your installed version truly uses create_or_derive_api_creds(), keep your name — but I’d verify by grep:

python -c "import py_clob_client; import inspect; from py_clob_client.client import ClobClient; print([m for m in dir(ClobClient) if 'derive' in m or 'api' in m])"

Also: one more thing to add (so you don’t silently break later)

After setting creds, immediately assert:

client.assert_level_2_auth()


So you fail fast at startup instead of during liquidation.
