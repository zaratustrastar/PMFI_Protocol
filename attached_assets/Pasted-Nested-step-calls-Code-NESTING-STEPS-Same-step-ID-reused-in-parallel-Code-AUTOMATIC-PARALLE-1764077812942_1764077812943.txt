Nested step.* calls → Code: NESTING_STEPS

Same step ID reused in parallel → Code: AUTOMATIC_PARALLEL_INDEXING

Let’s fix both in your polymarket-monitor workflow.

1. What’s going wrong conceptually
A. Nested step.* tooling

Somewhere in polymarketWorkflow you have something logically like:

await step.run("publish-all", async () => {
  // ❌ inside a step.run callback...
  await Promise.all(
    markets.map(market =>
      step.run("publish", async () => {       // ← nested step.run
        // send telegram
      })
    )
  );
});


Inngest does not allow calling step.run (or step.sleep, etc.) inside another step.run callback.
That’s what the NESTING_STEPS warning is about.

B. Same step ID in parallel

You likely also do something like:

await Promise.all(
  markets.map(market =>
    step.run("publish", async () => {  // ❌ same ID "publish" for many markets at once
      // ...
    })
  )
);


Because all those step.run("publish", ...) calls happen in parallel with the same ID, Inngest warns:

We detected that you have multiple steps with the same ID … Using the same IDs across parallel chains of work can cause unexpected behaviour.

That’s the AUTOMATIC_PARALLEL_INDEXING warning.

2. The pattern Inngest wants you to use

Two golden rules:

All step.run calls must live in the top-level function body, not inside another step.run callback.

Each parallel step.run must have a unique ID.

So instead of:

await step.run("publish-all", async () => {
  await Promise.all(
    markets.map(market =>
      step.run("publish", async () => { ... })
    )
  );
});


you want:

const markets = await step.run("fetch-markets", async () => {
  // fetch from Polymarket API
  return fetchedMarkets;
});

await Promise.all(
  markets.map((market, index) =>
    step.run(`publish-${market.id ?? index}`, async () => {
      // send telegram message for this market
    })
  )
);


Notice:

step.run("fetch-markets", ...) is not inside another step.

Each publish step has a unique ID (e.g. publish-1234).

3. Concrete “before → after” refactor template

I’ll give you a drop-in structure you can adapt.

❌ Likely current structure (simplified)
export const polymarketWorkflow = inngest.createFunction(
  { id: "workflow.polymarket-monitor" },
  { cron: "* * * * *" },
  async ({ step }) => {
    await step.run("monitor-and-post", async () => {
      const markets = await step.run("fetch-markets", async () => {
        // GET markets from Polymarket
      });

      await Promise.all(
        markets.map(market =>
          step.run("publish", async () => {
            // build message, send to Telegram
          })
        )
      );
    });
  }
);


Problems:

step.run("fetch-markets") and step.run("publish") are inside step.run("monitor-and-post") → nested.

"publish" is reused for many markets in parallel.

✅ Safe version

Refactor to this shape:

export const polymarketWorkflow = inngest.createFunction(
  { id: "workflow.polymarket-monitor" },
  { cron: "* * * * *" },
  async ({ step }) => {
    // 1) Fetch markets as one step
    const markets = await step.run("fetch-markets", async () => {
      // call Polymarket API here
      // return an array of markets
      return fetchedMarkets;
    });

    if (!markets || markets.length === 0) {
      return;
    }

    // 2) Publish each market as its own step (no nesting)
    await Promise.all(
      markets.map((market: any, index: number) =>
        step.run(`publish-${market.id ?? index}`, async () => {
          // build TG message, send via Telegram API
          // you can use your referral + category hashtag stuff here
        })
      )
    );
  }
);


This fixes both warnings:

No step.run inside another step.run.

Each publish step uses a unique ID.
