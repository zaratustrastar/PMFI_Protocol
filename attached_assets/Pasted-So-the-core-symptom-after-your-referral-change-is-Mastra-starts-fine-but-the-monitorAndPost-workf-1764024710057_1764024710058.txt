2. Most likely places where the referral integration broke things

Based on how you described integrating the referral links, the failure can be in three buckets:

A. The workflow file no longer loads

You probably edited the file that defines monitorAndPost and added some code like:

const addReferral = (url: string) => {
  const u = new URL(url); // ⬅ this can throw
  u.searchParams.set("via", "q2XDjZW");
  return u.toString();
};


If any top-level code in that file throws (e.g. new URL(undefined) when some URL is missing), then:

That module fails to load.

The workflow export never happens.

Mastra starts but never registers monitorAndPost with Inngest.

Result: no more scheduled runs and no “monitorAndPost” logs.

Nothing in your grep "error" showed up because:

The error might be logged without the word “error”, or

You’re only seeing high-level systemd logs, not the full Node stack trace.

B. The workflow is no longer exported / imported

If you touched imports/exports when adding the helper, a small mistake like this can silently “disappear” your workflow:

You moved monitorAndPost to another file and forgot to re-export it.

You changed a default export to a named export (or vice versa).

You removed it from workflows/index.ts (or wherever you collect them for Mastra).

Result: Mastra runs, but Inngest never sees that workflow → no executions, no logs.

C. The schedule or trigger got changed

Less likely but possible: when editing, you accidentally removed or changed the schedule/trigger:

// Before:
schedule: "*/1 * * * *", // every minute

// After:
schedule: "", // or comment removed, or env var undefined


or the event name changed. Then nothing will ever trigger it.

3) Add a safe helper for referral URLs

Whatever you currently use, I’d make it super defensive so it can’t kill the module:

const REF_CODE = "q2XDjZW";

export function addReferral(url?: string | null): string {
  if (!url || typeof url !== "string") return url ?? "";

  if (!url.includes("polymarket.com")) return url;

  try {
    const u = new URL(url);
    u.searchParams.set("via", REF_CODE);
    return u.toString();
  } catch (e) {
    console.error("[referral] Invalid URL, skipping:", url, e);
    return url; // fall back to original
  }
}


Key safety points:

Accepts undefined / null and just returns "" → no crash.

Only touches URLs containing polymarket.com.

Wraps new URL(...) in try/catch, logs, and continues.

No top-level execution with potentially bad URLs.

Then in your posting code:

const marketUrlWithRef = addReferral(marketUrl);

// Use marketUrlWithRef in the Telegram message
